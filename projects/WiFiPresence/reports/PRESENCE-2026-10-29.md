# Presence workbench verification, 2026-10-29

This is an implementation and transport report. It is not an occupancy-accuracy result or full MVP acceptance. The requester confirmed that no newer labeled recordings are available.

## Delivered

- `presence.py`: readiness, canonical audit, training, held-out evaluation, file inference, synthetic demo, and local server commands.
- An experimental NumPy logistic classifier over 20 numerical CSI features. This is a small supervised model, not a large language model. Features exclude scenario labels and fan state; scaling and fitting use development trials only.
- A loopback-only page for supplied NPZ examples, temporary NPZ uploads, training preflight, live input, and explicit UNKNOWN output.
- An optional ESPectre 3.0.0 live adapter with bounded duration, transport-error handling, stale-data checks, session cleanup, and original traffic-mode readback.
- Separate study manifests/inventories and JSON models, without editing the original pilot exclusions or raw files.

## Problems encountered

An initial control request omitted `/espectre/v1`; the live adapter now includes it. A later live attempt reproduced firmware send backpressure and ended after 276 packets, with one reported backpressure event and 108 dropped records. Cleanup also exposed a race between closing the raw TCP connection and the firmware releasing the session. The adapter now waits for the firmware's inactive state, avoids redundant traffic-mode mutations, and checks restoration. The 12-second success followed these fixes. Backpressure remains an explicit possible failure; it has not been proved eliminated.

## Remaining scientific work

1. Stabilize collection timing and obtain officially admitted S1 and S4 controls. Keep all failed captures and receipts.
2. Collect independently labeled repeats of all six conditions, with original-recording and acquisition-batch IDs. Record layout, person position/activity, calibration, fan state, and restoration evidence.
3. Split whole acquisition batches/recordings before fitting. Keep the test batch untouched during feature/threshold choices. The original recommended design is five recordings per condition, split 2 development / 1 validation / 2 test; more independent batches may be required by observed variability.
4. Audit the new study, fit a small candidate, and report validation/test results separately by condition, including UNKNOWN and failure cases. Stationary presence remains a hypothesis.
5. Evaluate fan changes under a clearly recorded calibration policy. Fan-on recalibration alone cannot establish fixed-model interference resistance. Onset markers are required for real response latency.

The code's one-per-condition-per-split preflight is only an engineering coverage floor, not a course requirement or adequate evidence for deployment. Cross-room/device generalization, continuous multi-hour sensing, multi-link fusion, router execution, and robust stationary presence remain unverified.
