# DINO PRO · 恐龙快跑加强版

参考 Chrome 离线小恐龙（[dinosaur.game](https://dinosaur.game/)）重制的**加强版**跑酷游戏。
纯前端、零依赖、零构建，4 个文件即可直接部署到 GitHub Pages。

核心增强：

1. **金币机制** —— 金币沿"起跳 → 落地"的抛物线铺开，单组可一次跳跃全收；右上角独立计数，结算时按连击倍率统一转成分数。
2. **键位重构** —— `W` / `空格` 跳跃，`S` 下蹲，`A` 减速，`D` 加速（按住持续微调）。
3. **变速操控** —— 0.70× ~ 1.60× 实时调速，画面左下角有速度表。
4. **触屏支持** —— 移动端自动显示虚拟按键。

## 操作说明

| 按键 | 作用 |
| --- | --- |
| `W` / `空格` / `↑` | 跳跃（**长按跳更高**，提前松开会被截断） |
| `S` / `↓` | 下蹲（**空中按下会加速下落**，用来快速落地） |
| `A` / `←` | 减速，最低 `0.70×` |
| `D` / `→` | 加速，最高 `1.60×` |
| `P` | 暂停 / 继续 |
| `M` | 静音开关 |

移动端：点击画面上半部分跳跃，底部四个虚拟按键对应 减速 / 跳跃 / 下蹲 / 加速。

### 加速减速的手感说明

- **按住** `D` 倍率会持续爬升（约 1.05/秒），**按住** `A` 持续下降（约 1.20/秒）。
- 松开按键后，倍率会**缓慢回归 1.00×**（约 0.62/秒），不会突然跳变。
- 加速能拉开与障碍的距离、但反应时间变短；减速更安全、但金币组通过速度变慢，各有取舍。

## 金币与连击规则

这是本作与原版最大的差别。

### 分布

金币的核心形态是**跳跃抛物线**：金币沿着恐龙"起跳 → 落地"的真实轨迹铺开，
高度刚好落在恐龙身体中部。所以**在弧线起点起跳，就能把整组金币一次全部收走**。

| 图案 | 权重 | 说明 |
| --- | --- | --- |
| `arc` | 高 | 标准抛物线，5~6 枚，一条完整跳跃弧 |
| `arcTight` | 中 | 短跨度抛物线，3~4 枚，小幅起跳即可收 |
| `ground` | 低 | 贴地金币串，3~4 枚，跑动即可收（节奏调剂） |

此外，仙人掌有约 32% 的概率附带一条**障碍弧**：从障碍左侧起跳、越过仙人掌、右侧落地，
一条完整抛物线正好铺满，跳过去的同一次操作就能把金币收完。

四条硬性规则保证每一组都拿得全：

- **不会同列堆叠** —— 任意两枚金币的水平间距恒大于 26px，不存在"同一横坐标上下各一枚"这种被迫二选一的排布。
- **起跳点与落地点一定是干净的** —— 每枚金币带方向性保护区：弧线**起点只管左侧**（留起跳助跑），弧线**终点只管右侧**（留落地缓冲）。保护区按**时间**换算（保护时间 × 当前速度），所以速度越快、留出的像素距离越大，玩家实际感受到的反应时间始终一致。谁先出现谁占位：金币先来，仙人掌就等它滚远；仙人掌先来，金币组就等路面清空。
- **守卫弧中段刻意不加保护** —— 架在仙人掌正上方的那几枚金币是设计的一部分（"跳过障碍的同时正好收完"），不计入避让。
- **不会互相挤** —— 金币组与既有金币之间也会互相避让，屏幕上永远只会出现一组干净的弧线。

> 保护区参数：起跳点 / 落地点 `0.50 秒`（下限 140px）、弧线中段 `0.20 秒`（下限 80px）、贴地串 `0.28 秒`（下限 100px）。

金币组之间按**时间**计时（1.8~2.5 秒一组），所以无论玩家加速还是减速，密度都保持一致。

> 想让金币更密或更稀，改 `game.js` 里 `spawnCoinGroup()` 末尾的 `rand(1.8, 2.5)` 即可，单位是秒。

### 倍率阶梯

每吃一枚金币，连击数 +1；单枚金币基础分 **10 分**，实际得分 = `10 × 当前倍率`。

| 连击数 | 倍率 |
| --- | --- |
| 0 ~ 7 | `×1.0` |
| 8 ~ 17 | `×1.5` |
| 18 ~ 29 | `×2.0` |
| 30 ~ 44 | `×2.5` |
| 45+ | `×3.0`（上限） |

> 举例：一口气吃掉 20 枚金币 = 7×10 + 10×15 + 3×20 = **280 分**。

### 断连击

**只要有一枚金币从恐龙身后滑出屏幕而没被吃掉，连击立即清零**，右上角连击条会红闪提示。
所以"该不该为了几枚金币冒险起跳"是本作的核心决策点。

## 结算

撞到仙人掌或翼龙后进入结算面板，逐项列出：

- **距离分** —— 位移 × 0.1
- **收集金币** —— 本局枚数
- **金币转化分** —— 按连击倍率累加后的分数
- **总分** —— 距离分 + 金币转化分
- **历史最高分** —— 破纪录时显示「新纪录」徽章
- **累计收集金币** —— 跨局累计，长期成就感

最高分与累计金币通过 `localStorage` 持久化（键名 `dinopro.save.v1`）。

## 障碍与难度

| 障碍 | 尺寸 | 应对 |
| --- | --- | --- |
| 小仙人掌 | 18×34 | 跳（可 1~3 株连排） |
| 大仙人掌 | 22×50 | 跳，连排时需提前起跳 |
| 低空翼龙 | 离地 8 | **必须跳**，蹲下躲不掉 |
| 中空翼龙 | 离地 34 | **必须蹲**，站着会撞 |
| 高空翼龙 | 离地 52 | 不用管，但**乱跳会撞** |

- 基础滚动速度从 `340 px/s` 随距离线性增长到上限 `640 px/s`。
- 实际速度 = 基础速度 × 玩家倍率，所以**主动减速可以给自己争取反应时间**。
- 分数超过 260 后翼龙开始出现，难度越高出现频率越高，高难度下还会成群出现。

### 成群翼龙为什么不会变成死局

翼龙成群时**整群必须是同一个高度**：低空只能跳、中空只能蹲、高空不能乱跳。
一旦混高度，玩家跳完第一只、落地正好撞上第二只 —— 那是无解的死局。

- 同一群的翼龙**紧贴排列**（群内间隙 6~18px），像仙人掌连排一样，
  一次跳跃（低空）或一次下蹲（中空）就能整群通过。
- 群规模按"一次满跳能覆盖多宽"反算：`span = 速度 × 满跳窗口 × 0.72 - 碰撞箱宽`，
  并设**硬上限 3 只**，高速时也不会刷出一整排"翼龙墙"。
- 相邻障碍组的间隔**按时间换算**（`0.70~0.86 秒 × 当前速度`），速度越快像素间距越大，
  保证两个"必须跳"的障碍之间始终留得下一次完整跳跃的滞空距离。

> 验收方式：`.deepworks/tmp/test-dino.js` 里有一个"完美玩家"模拟器（自动在正确时机起跳、
> 中空翼龙落地时下蹲），在满难度 `640 px/s` 下连跑 90 秒，要求 **0 碰撞**。

## 布局与性能

### 状态栏为什么必须放在画布之外

早期版本把分数、金币和 SPEED 速度条用 `position: absolute` 叠在 `#game` 画布上。
游戏逻辑尺寸固定 `800x200`（4:1），手机竖屏时 `.stage` 只有约 `390x98` 像素：
顶部 HUD 约占 55px、底部速度条约占 26px，两者相加几乎盖满整个画面，
而恐龙站在逻辑 `y=55..76`（手机端约 `y=27..37`）正好被压住 —— 这就是
"显示 SPEED 的那一栏把半个游戏界面挡住、根本看不到障碍物"的原因。

现在改为 `.hudbar`，作为 `.stage` 的**兄弟节点**排在画布上方（`display: flex; flex-wrap: wrap`），
窄屏时 SPEED 条自动换到第二行，也不再覆盖画面：

| 视口 | 旧：画面尺寸 | 旧：HUD 遮挡 | 新：画面尺寸 | 新：遮挡 |
| --- | --- | --- | --- | --- |
| 390×844 手机竖屏 | 358×90 | 100%（压住恐龙） | 390×98 | 0% |
| 844×390 手机横屏 | 812×203 | 45%（压住恐龙） | 812×203 | 0% |
| 768×1024 平板竖屏 | 736×184 | 49%（压住恐龙） | 768×192 | 0% |
| 1440×900 桌面 | 940×235 | 39% | 1280×320 | 0% |

### 画面尺寸的取舍

游戏视野必须保持 4:1，且**逻辑宽固定为 800：改逻辑宽等于改难度**
（W=800 时满速 640px/s 的反应时间约 1.15s，W=480 时只剩 0.65s）。
所以"画面太小"不能靠缩小逻辑宽解决，只能：

1. 放宽桌面容器 `max-width` 940px → 1280px；
2. 手机端 `.stage-wrap { margin-inline: -16px }` 左右全出血，吃掉页面内边距；
3. 矮视口按可用高度收缩：`width: min(100%, max(240px, calc((100dvh - 220px) * 4)))`；
4. 手机横屏（`hover: none and max-height: 520px`）隐藏品牌栏，并把高度预算放宽到 `150px`，
   让横屏画面不小于旧版且整页无需滚动；
5. 触屏设备隐藏键盘提示行（`.legend` / `.footnote`），把竖向空间让给画面。

`body` 改为 `flex-direction: column`，配合 `.app { margin-block: auto }` 做垂直居中：
内容比视口矮时居中（消除下方大片空档），内容超高时 auto margin 自动退化为 0，从顶部开始正常滚动。

### 起跳卡顿的原因与修复

卡顿来自**追帧快进**，不是逻辑帧率不够。主循环是 120Hz 固定步长：

```js
acc += dt;
while (acc >= STEP && guard++ < 10) { update(STEP); acc -= STEP; }
```

某帧一旦变慢（GC、样式重排、系统调度），`acc` 就会积压；而 `guard < 10` 允许单帧连补 10 步，
于是下一帧一次性推进 83ms 的模拟量 —— 跳跃弧线看起来就是"顿一下再窜出去"。

修复：把积压上限钳到 `MAX_CATCHUP = 0.10` 秒，`MAX_STEPS = ceil(0.10 / STEP) + 2 = 14` 保证永不截断：

```js
if (acc > MAX_CATCHUP) acc = MAX_CATCHUP;   // 丢弃积压，杜绝追帧快进
```

次要原因一并处理：`updateHUD` 原来每 60ms 无条件写 `spFill.style.width/left/backgroundColor`，
会触发包含画布的 `.stage` 样式重算。现在缓存上次写入的值，**值没变就完全不碰 DOM**；
速度条颜色改由 `data-dir` 交给 CSS（`.sp-fill[data-dir='fast'|'slow']`），不再写内联样式。

## 部署到 GitHub Pages

假设你已经有一个 `<用户名>.github.io` 仓库（个人主页仓库）。

### 方式一：作为子目录（推荐，不会覆盖现有主页）

1. 在本仓库中新建目录，例如 `dino/`。
2. 把 `index.html`、`style.css`、`sprites.js`、`game.js` 四个文件放入 `dino/`。
3. 提交并推送：

   ```bash
   git add dino
   git commit -m "add dino pro game"
   git push
   ```

4. 访问 `https://<用户名>.github.io/dino/` 即可游玩。

### 方式二：在主页加入口

在你主页的导航或卡片区加一个链接：

```html
<a href="./dino/">🦖 DINO PRO · 恐龙快跑加强版</a>
```

### 方式三：独立仓库

新建一个公开仓库（例如 `dino-pro`），把 4 个文件推到 `main` 分支，然后在
`Settings → Pages` 中选择 `Deploy from a branch` → `main` → `/ (root)`。
稍等片刻即可通过 `https://<用户名>.github.io/dino-pro/` 访问。

> 注意：所有资源都使用相对路径引用，因此放在**任意子目录**下都能正常工作，无需修改代码。
